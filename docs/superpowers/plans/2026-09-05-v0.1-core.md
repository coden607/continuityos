# ContinuityOS v0.1 Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a working ContinuityOS v0.1 core with capability routing, context continuity, health-aware failover, typed agent messages, CLI/API surfaces, secret-safe defaults, CI, and a minimal PWA shell.

**Architecture:** The Python core is dependency-light and owns stable domain schemas plus deterministic routing/continuity logic. FastAPI and Typer are thin adapters. Frontend and future model/MCP integrations consume these contracts rather than embedding provider behavior.

**Tech Stack:** Python 3.11+, Pydantic 2, FastAPI, Typer, Pytest, React/Vite/TypeScript PWA shell, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-05-continuityos-v1-design.md`

## Global Constraints
- $0-first development; no paid service is required.
- No plaintext secrets in Git.
- Provider-neutral contracts; no provider-specific logic in the core router.
- Consequential actions must be guardrail-able and authorization-aware.
- Self-healing excludes autonomous production code mutation.
- Context handoff uses structured Context Capsules.
- Unhealthy or quarantined providers are excluded from routing.
